## Key Design Decisions

### 1. **Immediate Local Preview**
- **Why:** User sees result instantly, no waiting for upload
- **How:** `URL.createObjectURL()` creates temporary local URL
- **Trade-off:** URL is temporary but provides instant feedback

### 2. **Progressive Enhancement**
- **Why:** Works without Firebase, better with it
- **How:** Check if Firebase is available before using
- **Trade-off:** More complexity but better user experience

### 3. **Dual Storage**
- **Why:** Redundancy and offline support
- **How:** Save to both Firebase and localStorage
- **Trade-off:** More storage used but more reliable

### 4. **Real-time Listeners**
- **Why:** Updates appear without manual refresh
- **How:** Firebase `.on('value')` event listeners
- **Trade-off:** Constant connection but better UX

### 5. **Progress Feedback**
- **Why:** Users know upload status
- **How:** Firebase `uploadTask.on('state_changed')`
- **Trade-off:** More UI code but clearer communication

## Performance Characteristics

| Operation | Time | Notes |
|-----------|------|-------|
| Local preview | <100ms | Instant feedback |
| Firebase init | 500-1000ms | One-time per session |
| Upload 10MB video | 5-30s | Depends on connection |
| Database save | 200-500ms | After upload completes |
| Real-time sync | 500-2000ms | Device receives update |
| Video load from cloud | 2-10s | First time (then cached) |
